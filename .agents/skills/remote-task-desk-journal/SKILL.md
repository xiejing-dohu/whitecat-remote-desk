# 远程任务台工作记录

在本 skill 所在的项目根目录使用唯一日志 `操作记录.md`。进入项目先读根目录 AGENTS.md 及日志末尾的检查点。如果用户指定了旧聊天，读取引用并以实际文件和应用状态复核。

1. 在修改文件、操作 Axure、启动耗时验证或执行外部动作**之前**，追加一行「开始」，写明步骤号、目标、文件或页面，以及可用来判定成功的证据。先把记录落盘，再做操作。
2. 操作返回后立即以相同步骤号追加「完成」「失败」「部分完成」或「阻塞」，写明做了什么、关键结果、产物位置和下一步。读取、查询、命令和测试也要入账。连续只读检查可以成组记录，逐项列出检查对象和结果。并发工作每个动作都要能对应到结果。
3. 日志使用 UTF-8，按时间追加，时间写为当地时间并注明时区。错误保留可诊断的短摘要；命令、路径、工具名、页面名和验证条件要足以重新定位。记录写入本身由其所在条目覆盖。省略密码、令牌、Cookie、配对凭据和私密聊天正文。
4. 遇到连接重置、进程中断或聊天切换，从最后一个只有「开始」的步骤恢复。先核对目标文件、页面、后台进程或测试结果，再决定补记成功、继续剩余部分或重试。特别是在 Axure 中，先确认活动文档和现有交互，再添加或保存。
5. 交接或收工时，在同一文件末尾写检查点，列出最后验证通过的内容、尚未确认的内容，以及下一条能直接执行的操作。分别标明 HTML 浏览器实测、RP 原生行为验证、历史聊天转述和设计意图。
6. 测试与演示复用原有的白猫工作台镜像窗口。需要两台模拟器时，接收机在后台通过 ADB 验收。用户明确要求增加窗口时再开启额外镜像。
